# 인쇄 및 PDF 내보내기 공통 준수 규칙

문서 ID: `MDPRO-PRINT-PDF-CONTRACT`  
규칙 버전: `1.0.0`  
기준일: `2026-10-20`  
기준 구현: WebDAV MDPRO 로컬 소스. MDproViewer를 포함한 다른 Markdown 앱으로 이식할 때도 적용한다.

## 1. 효력과 적용 범위

이 문서는 단순한 구현 설명이 아니라 **출력 결과의 준수 계약**이다. 인쇄, 브라우저의 PDF로 인쇄, 앱의 PDF 내보내기, 해당 미리보기와 저장 처리에 적용한다.

- **필수(MUST)**: 반드시 만족해야 한다. 미충족 항목이 있으면 전체 규칙 준수로 표시할 수 없다.
- **금지(MUST NOT)**: 구현 편의나 라이브러리 제약을 이유로 사용해서는 안 된다.
- **권장(SHOULD)**: 다른 방법을 선택하면 동등한 결과를 입증하고 이유를 기록한다.
- 구현 함수명·DOM ID·프레임워크·저장소는 변경할 수 있지만, 규칙 ID에 대응하는 사용자 동작과 결과는 유지해야 한다.
- 버그나 미완성 fallback은 규칙이 아니다. 기준 코드와 필수 규칙이 충돌하면 필수 규칙을 기준으로 수정·검증한다.
- 사용자에게 명시적으로 승인받은 요구 변경은 우선 적용하되, 변경한 규칙 ID·이유·검증 결과와 규칙 버전을 기록한다. 기존 기능 삭제를 이식의 부수 효과로 처리해서는 안 된다.

이 파일을 다른 저장소에 복사하는 것만으로 기능이 구현되거나 자동 강제되는 것은 아니다. 대상 앱의 지침 연결, 구현 대응표 작성, 회귀 테스트와 실제 출력 검증까지 완료해야 준수로 판정한다.

## 3. 인쇄 전용 규칙

### P-01. 문서만 출력

인쇄 버튼, 편집기 안의 Ctrl+P/Cmd+P, 호스트 화면의 Ctrl+P/Cmd+P, 브라우저 메뉴 인쇄가 문서 출력으로 연결되어야 한다. 메뉴 인쇄의 `beforeprint` 경로도 준비한다. 메뉴 경로는 비동기 작업을 기다리기 어려우므로 최신 렌더링을 유지하거나 준비된 사본을 제공해야 한다.

iframe으로 편집기를 담은 앱은 부모의 탐색기·분할 패널 폭과 높이로 출력하지 않는다. 기준 구현은 접근 가능한 동일 출처 최상위 문서에 출력 사본을 배치한다. 다른 출처의 부모에 접근할 수 없다면 별도 출력 문서 등 동등한 격리 방식을 구현하고 실제 출력으로 검증한다.

### P-02. 화면용 A4와 실제 인쇄 페이지 구분

화면용 `.a4-sheet`, `.a4-view-content`, `.a4-atomic-content` 같은 뷰포트는 본문만 꺼내 실제 용지에서 다시 흐르게 한다. 화면 페이지 번호와 조작 버튼을 제거한다. 화면에서 자동 분할된 페이지마다 강제 개행해 빈 페이지를 만들어서는 안 된다.

사용자가 의도적으로 지정한 출력용 페이지 나눔은 화면 자동 분할과 구분해 보존한다. 대상 앱의 명시적 페이지 나눔 문법과 대응 방식을 기록한다.

### P-03. 긴 수식의 폭 맞춤

1. 수식은 완성된 렌더링 객체를 기준으로 측정한다. MathJax의 `mjx-math`, KaTeX의 `.katex-html` 또는 동등한 실제 수식 영역을 사용한다.
2. 사용 가능 폭은 용지 본문 폭과 수식이 들어 있는 목록·표 셀·인용문 등의 **실제 내부 폭 중 작은 값**이다. 패딩과 안전 여유를 뺀다.
3. 넘치는 수식만 비례 축소한다. 짧은 수식과 문서 전체 글자 크기는 유지한다.
4. 축소할 때 분자·분모·루트·괄호·첨자·기호를 하나의 수식으로 보존한다. 가로만 눌러 비율을 왜곡하지 않는다.
5. 같은 사본에 준비 처리를 반복해도 추가로 작아지지 않아야 한다. 원래 배율을 복원해 측정한 뒤 필요한 배율을 다시 계산한다.
6. 수식의 스크롤바와 `overflow:hidden/auto`에 의존한 가림을 인쇄에 남기지 않는다. 축소 후 가로·세로 배치 공간도 함께 맞춘다.

```text
허용 폭 = min(용지 본문 폭, 수식 부모의 내부 폭) - 안전 여유
추가 배율 = min(1, 허용 폭 / 원래 렌더링 폭)
출력 배율 = 원래 배율 × 추가 배율
```

기준 구현의 안전 여유는 2 CSS px이며 A4 기본 본문 폭인 180mm에서 측정한다. 다른 용지·가로 방향·사용자 지정 여백을 지원하는 앱은 **실제 설정으로 본문 폭을 계산**해야 한다. 180mm를 모든 설정의 공통 상수로 복사해서는 안 된다.

`=` 뒤 줄바꿈은 선택 가능한 개선 방식이다. 적용하려면 TeX/MathML 구조를 사용해 출력 사본에서만 의미를 보존하는 다중 행 수식으로 만든다. DOM 글자나 문자열의 `=`를 무조건 잘라 분수·정렬·조건식을 손상시키는 처리는 금지한다. 줄바꿈이 안전하지 않으면 비례 축소를 사용한다.

### P-04. 인쇄 수명과 복구

- 인쇄창이 열린 동안 출력 DOM을 유지한다. `window.print()`가 반환됐다고 즉시 삭제하지 않는다.
- `afterprint`와 인쇄 미디어 종료를 기준으로 임시 DOM·스타일·이벤트·타이머를 정리한다. 취소·실패 후에도 원래 앱으로 복구되어야 한다.
- 기준 구현의 300초 정리 타이머는 이벤트 미발생에 대비한 보조 수단이다. 짧은 타이머를 주 정리 방식으로 사용해서는 안 된다.
- 이미 준비한 호스트 출력 사본의 스타일을 `beforeprint`에서 무조건 제거·재생성하지 않는다. 브라우저가 출력 배치를 잡는 중 스타일이 사라지는 경합을 방지한다.

## 4. PDF 내보내기 전용 규칙

### D-01. 미리보기와 저장 결과

실제 A4 크기의 페이지를 만들어 페이지 내부에서 객체를 배치하고, 저장은 같은 배치와 객체 편집 상태를 사용한다. 화면 맞춤 배율은 화면 표시용이다. 저장할 때 미리보기 확대·축소와 스크롤 위치에 의해 PDF 내용이 작아지거나 잘려서는 안 된다.

기본 여백은 15mm이며 현재 제공되는 여백은 10·15·20·25mm이다. 여백 변경 시 객체를 다시 측정하고 재분할한다. PDF와 브라우저 인쇄는 서로 다른 페이지 나누기 엔진을 사용할 수 있으므로 페이지 수가 반드시 같을 필요는 없지만, 내용의 완전성과 읽기 가능성은 모두 만족해야 한다.

### D-02. 페이지 분할

- 긴 문단은 단어·문장과 DOM 구조를 가능한 한 유지해 나눈다. 자른 앞부분과 뒷부분을 합치면 원래 내용이 복원되어야 한다.
- 목록과 컨테이너를 나눌 때 순서·중첩·서식을 유지한다.
- 명시적 페이지 나눔, 사용자가 선택한 앞에서 나누기·앞쪽 페이지에 붙이기와 그 실행 취소를 지원한다. 붙이기도 용지 밖으로 넘기는 명령은 아니다.
- 이미지·도표·수식은 부분 픽셀로 잘라 다음 페이지에 이어 붙이지 않는다. 전체가 들어가는 페이지로 옮기거나 비율을 유지해 맞춘다.
- 페이지 높이를 넘는 객체를 `max-height`와 `overflow:hidden`으로 잘라서 강제로 맞추는 처리는 금지한다. 안전한 분할·축소가 불가능하면 실패 이유를 알린다.

### D-03. 표

현재 페이지에 들어갈 행이 있으면 그 공간을 활용하고 나머지를 다음 페이지로 넘긴다. 표 전체를 다음 페이지로 보내 제목 아래를 불필요하게 비워두는 처리를 피한다.

표 분할 시 열 구조·너비·테두리·셀 내용·행 순서와 병합 셀을 보존한다. `rowspan` 범위를 가로지르는 임의 분할을 금지한다. 이어지는 표에는 헤더를 반복하고, 표 제목은 첫 조각에, footer는 마지막 조각에 둔다. 한 행 또는 병합 묶음 자체가 페이지보다 크면 별도의 안전한 처리와 검증이 필요하다.

### D-04. 수식 보존

- MathJax·KaTeX·MathML·원시 TeX를 인식하고, 출력 사본에서 원본 정보를 가진 독립 수식 객체로 보존한다.
- 기준 구현은 MathML/TeX 또는 완전한 SVG를 로컬 MathJax SVG 엔진으로 처리해 SVG 이미지 객체를 만든다. 공유 SVG 글리프 참조가 끊겨 기호가 사라지는 출력을 금지한다.
- 수식은 페이지 분할에서 글자들의 집합이 아닌 **불가분 객체 1개**로 취급한다. 수식 전후 문장은 정상 분할하되 수식은 정확히 한 번만 포함한다.
- 이미지의 원래 비율을 유지하고 최종 부모 폭에 `max-width:100%`, 자동 높이 또는 동등한 제약을 적용한다. 목록·표 셀 내부의 좁은 폭에서도 수식 전체가 보여야 한다.
- 수식 픽셀의 디코딩이 끝나기 전에 측정·저장하지 않는다. 수식 원본 누락, 잘못된 수식, 글리프 손실 또는 변환 실패 시 PDF 저장을 차단하고 오류를 알린다.
- `pre`·`code` 안의 `$...$`는 코드로 보존한다. 수식으로 변환하지 않는다.

### D-05. Mermaid 및 이미지

Mermaid의 원본 코드, 라벨·색상·배치와 이미지 비율을 보존한다. 화면에서 드래그·확대한 래퍼의 잘린 뷰포트를 캡처하지 않는다. PDF는 완성된 도표를 이미지로 변환해 배치한다.

기준 PDF 경로는 공통 고해상도 PNG 변환기를 사용한다. PNG 목표 배율·라벨·SVG 정리와 DOCX 연계의 세부 규칙은 [Mermaid 이미지 변환 기술 가이드](MERMAID_IMAGE_EXPORT_TECHNICAL_GUIDE.md)를 함께 따른다. 인쇄의 기준 구현은 SVG 이미지 경로를 사용하므로 PDF와 같은 변환 함수를 쓴다고 가정해서는 안 된다.

미리보기의 이미지 크기 조절은 비율을 유지하고 재분할 및 실제 저장 결과에 반영한다. 미리보기 핸들·선택 테두리·수정 도구는 PDF에 포함하지 않는다.

### D-06. 코드와 표의 가독성

코드는 줄바꿈을 허용하고, 긴 한 줄 때문에 오른쪽이 잘리지 않도록 한다. 기준 코드는 진한 글자 `#0f172a`, 밝은 배경 `#f1f5f9`, 구분 가능한 테두리를 사용한다. 표의 헤더·본문·경계도 흰 용지에서 구분되어야 한다.

### D-07. 편집 상태와 저장

PDF 미리보기의 여백, 객체 줄 간격·내용 수정, 이미지 크기, 수동 분할·붙이기, 실행 취소 기능을 유지한다. 출력용 수정은 원본 Markdown과 분리한다.

설정은 문서 키와 원본 서명으로 연결한다. 원본이 달라지면 예전 객체 인덱스의 수정 상태를 무조건 적용하지 않는다. 저장된 사용자 선택을 기본값으로 덮어쓰지 않는다. 저장 실패를 성공으로 표시하지 않는다.

| 표준 | 2 | 0.90 | 저장값이 없을 때 기본 |
| 고품질 | 3 | 0.97 | 아니오 |

엔진이 달라지면 수치 대신 동등 이상의 품질을 입증하고 대응표에 기록한다. 품질 선택은 문서의 물리 크기나 내용의 완전성을 바꾸는 기능이 아니다.

저장 전 확인, 0~100% 진행률, 중지 기능을 제공한다. 페이지를 순서대로 처리하며 취소 여부를 작업 경계마다 확인한다. 취소·오류 후 불완전한 파일을 정상 파일로 내려받게 하지 않는다. 백그라운드 변환 중에도 진행률·완료·실패를 확인할 수 있어야 한다.

현재 기준 PDF는 페이지별 canvas → JPEG → jsPDF 경로로 생성된다. **검색·텍스트 선택 가능한 PDF나 벡터 PDF를 제공한다고 표시해서는 안 된다.** 다른 앱이 텍스트/벡터 엔진을 사용해도 위의 배치·보존 규칙은 동일하게 적용된다.

## 5. 기준 구현 연결표

경로는 이 저장소 기준이다. 다른 앱에서는 경로를 그대로 요구하지 않고 동등한 역할의 파일을 기록한다.

| 역할 | 기준 파일·진입점 |
| --- | --- |
| 인쇄 사본과 준비 | `mdpro/js/app.js`: `syncPrintRootFromViewer()`, `printPage()` |
| 긴 수식 비례 축소 | 같은 파일: `fitPrintMath()` |
| iframe 호스트와 메뉴/단축키 | 같은 파일: `getDocumentPrintWindow()`, `syncHostPrintDocument()`, `installDocumentPrintHandlers()` |
| 인쇄 용지·가독성·overflow | `mdpro/css/style.css`: `@media print`, `#print-root` |
| PDF용 렌더링 준비 | `mdpro/js/app.js`: `createPdfRenderedElement()`, `withPreparedMermaidExportViewer()` |
| PDF 분할·표·미리보기·저장 | `mdpro/js/export/pdf-export.js`: `openPreview()`, `paginate()`, `splitTableRows()`, `generatePdf()` |
| PDF 수식 보존 | `mdpro/js/export/pdf-math-preserve.js`: `prepare()` |
| Mermaid 변환 | `mdpro/js/mermaid/mermaid_render.js` 및 Mermaid 기술 가이드 |
| 캐시 갱신 | `mdpro/index.html`의 관련 자원 버전, `mdpro/Apps/PWA/service-worker.js` |

## 6. 확인된 구현 범위와 미완료 사항

이 절은 기준 코드의 현황이며 필수 규칙의 예외 허가가 아니다. 로컬 구현 확인은 배포 완료나 실제 프린터 출력 확인과 다르다.

| 항목 | 현황과 준수 판정 |
| --- | --- |
| 인쇄 본문 격리·호스트 폭 분리 | 로컬 구현 및 브라우저 PDF 인쇄 검증 경로가 있다. 대상 앱에서는 다시 검증한다. |
| 긴 HTMT 인쇄 수식 | A4 15mm, 큰 글자 예제에서 약 782px → 약 650px, 약 83% 축소와 짧은 수식 크기 유지를 확인했다. 모든 용지·모든 수식에 대한 포괄 검증은 아니다. |
| 인쇄의 다른 용지·사용자 여백 | `fitPrintMath()`는 현재 180mm를 기준으로 측정한다. 다른 설정에 대한 자동 적응을 보장하지 않는다. 지원 범위를 넓히려면 P-03에 따라 구현·검증한다. |
| PDF 과대 객체 fallback | `paginate()`에 최종적으로 `maxHeight`와 `overflow='hidden'`을 적용하는 경로가 남아 있다. **D-02/C-08 완전 준수 판정에서 미해결**이다. 이를 이식의 표준 처리로 복사하지 않는다. |
| 일반 이미지 로딩 실패 | 인쇄의 15초 대기와 오류 이벤트는 대기를 종료하지만 모든 일반 이미지 실패를 저장 차단으로 처리하는 것은 아니다. C-08 완전 준수에는 실패 식별·알림을 보완해야 한다. |
| PDF 형식 | 이미지 기반 페이지 PDF이다. 검색 가능 텍스트 보장을 하지 않는다. |
| 실제 하드웨어 출력 | 브라우저 출력/PDF 검증과 구분해 별도 기록한다. 실제 종이 출력까지 확인하지 않았다면 그렇게 명시한다. |

## 7. 이식 시 필수 절차

1. 대상 저장소에 이 문서와 Mermaid 기술 가이드를 함께 복사한다. 규칙 ID와 버전을 유지한다.
2. 아래 지침을 대상 앱의 `AGENTS.md` 또는 같은 역할의 개발 지침에 연결한다.
3. 대상 앱의 인쇄 버튼, 단축키, 메뉴, iframe/팝업/독립 창, PDF UI, 저장소, 렌더링 엔진을 먼저 조사한다. 같은 라벨의 다른 패널을 수정하지 않는다.
4. 이 문서의 모든 C/P/D 규칙에 대해 대상 구현 파일·함수와 `준수 / 미해결 / 해당 없음`을 기록한다. `해당 없음`에는 이유가 필요하며 공통 내용 보존 규칙을 제외할 수 없다.
5. 기존 저장 선택과 기능을 보존하면서 출력 사본·측정·분할·수식·저장 흐름을 연결한다. 라이브러리·로컬 MathJax·글꼴·이미지 자산의 경로와 라이선스도 함께 이식한다.
6. 회귀 테스트를 이식하거나 동등한 테스트를 작성한다. 브라우저/설치 앱에서 실제 UI와 생성 파일을 확인한다.
7. 배포 앱은 빌드·캐시 버전·서비스 워커·실제 제공 포트를 확인한다. 데스크톱 패키지 요청이면 패키지를 재빌드하고 그 패키지로 검증한다.
8. 미해결 필수 항목이 있으면 부분 준수로 보고한다. “전체 준수”, “정상 출력 보장”이라고 완료 처리하지 않는다.

## 8. 검증 항목과 합격 기준

### 자동 회귀 검사

이 저장소에서는 다음을 실행한다. 다른 앱은 같은 실패를 검출하는 동등한 테스트를 제공해야 한다.

```bash
node --check mdpro/js/app.js
node --test tests/printPdfLayout.test.mjs tests/printMathFit.test.mjs tests/pdfMathPreservation.test.mjs tests/pdfMermaidExport.test.mjs tests/pdfImageResize.test.mjs

```

`tests/fixtures/pdf-math-preservation.html`과 `tests/fixtures/pdf-table-flow.html`은 실제 브라우저용 회귀 자료이다. 테스트 통과나 빌드 성공만으로 실제 출력 검증을 대체하지 않는다.

### 실제 출력 검증 행렬

| 사례 | 합격 기준 |
| --- | --- |
| 좁은 iframe 안의 긴 문서 | 호스트 탐색기는 나오지 않고 용지 본문 폭을 사용한다. 문서 끝이 포함되고 불필요한 빈 페이지가 없다. |
| 버튼·편집기 단축키·호스트 단축키·메뉴 | 모두 문서를 출력한다. 취소 후 앱이 복구되고 두 번 연속 실행해도 정상이다. |
| A4 화면 페이지·연속 문서 | 화면 확대율과 고정 높이로 잘리지 않는다. 화면 자동 분할과 명시적 나눔을 구분한다. |
| 큰 글자 HTMT 긴 분수식 | 분자·분모·루트·오른쪽 마지막 항이 모두 본문 내부에 있다. 가로 스크롤바와 잘림이 없다. |
| 짧은 수식·반복 준비 | 짧은 수식은 원래 크기, 긴 수식은 같은 배율을 유지한다. 준비 횟수에 따라 계속 작아지지 않는다. |
| 목록·표 셀 속 수식 | 용지 전체 폭이 아닌 해당 부모의 내부 폭을 지킨다. |
| 페이지 경계의 수식 | 수식 수와 순서가 일치하며, 분수·첨자 전체 및 앞뒤 문장이 한 번씩 보존된다. |
| 매우 긴 표·병합 셀 | 모든 행이 순서대로 있고 헤더가 반복된다. 병합 셀이 임의로 절단되거나 중간 행이 사라지지 않는다. |
| 코드·다크 모드 | 코드의 긴 줄이 잘리지 않고 흰 용지에서 읽힌다. 코드 속 달러 문자는 수식으로 바뀌지 않는다. |
| Mermaid·큰 이미지 | 라벨·색상·비율이 보존되고 뷰포트가 잘리지 않는다. 이미지 크기 조절이 PDF 저장에 반영된다. |
| 미리보기 편집·저장 | 여백·수동 분할·줄 간격·객체 수정·실행 취소 상태가 저장에 반영된다. 원본은 바뀌지 않는다. |
| 재열기·원본 변경 | 같은 원본은 상태를 복원하고, 변경된 원본에 이전 객체 수정을 잘못 적용하지 않는다. |
| 이미지·수식 오류·중지 | 오류나 취소를 알리고 불완전한 결과를 성공 파일로 내보내지 않는다. |
| 과대 단일 객체 | 숨겨서 맞추지 않는다. 전체 보존 또는 명확한 실패 처리로 끝난다. |

모든 생성 PDF의 첫 페이지·중간 페이지·마지막 페이지와 객체 경계 페이지를 렌더링해 확인한다. DOM에서 준비가 끝났다는 로그만으로 수식 픽셀 보존을 판정하지 않는다. 이미지 기반 PDF는 텍스트 추출만으로 내용 누락을 검증할 수 없으므로 이미지 검토와 원본 객체 수·순서 대조를 함께 사용한다.
