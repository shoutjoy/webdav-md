## 1. 목적과 용어

Mermaid Ref는 Mermaid 코드를 직접 편집하고 다이어그램을 미리 보며 문서에 코드 또는 이미지로 넣는 도구다. Jena ME는 그 안의 AI 보조 영역이다. 이미지·참고 텍스트로 새 코드를 만들거나, 기존 코드와 수정 지시로 코드를 변경한다.

주요 사용 흐름은 ① 샘플/직접 코드 편집 → 미리보기 → 문서 삽입, ② 이미지/텍스트 → AI 생성 → 코드 확인 → 삽입, ③ 가져온 코드 → 수정 지시 → 검증된 수정 결과 적용이다. 코드 수정 모드는 참고 이미지·참고 텍스트와 입력을 분리한다.

### 3.1 호스트 창과 내부 툴바

`openMermaidEditorModal()`은 선택 텍스트를 기억하고 iframe을 지연 로드한 뒤 우측 Dock으로 연다. 다시 열 때 이전 플로팅/전체화면 상태를 초기화하는 코드가 있다. 외부 창 배치와 내부 도구 메뉴의 가로/세로 플로팅은 서로 다른 기능이다.

내부 메뉴는 저장값이 없으면 접힌 가로형이다. 접힌 상태에도 샘플 선택, 메뉴 펼치기, 코드로 문서삽입, SVG 이미지 넣기, PNG 이미지 넣기, UI 테마를 노출한다. 펼친 상태에서 방향 TD/LR, Config 삽입, 노드·연결 생성, 샘플·문법 튜토리얼·오류 자동수정·복사·SVG/PNG 다운로드·SVG→PNG 변환기에 접근한다. 세로 플로팅은 드래그와 크기 저장을 지원한다.

### 3.2 시각 디자인

밝은 화면과 `body.ui-dark` 화면을 지원한다. 패널 경계선·둥근 모서리·간격으로 입력/작업 영역을 구분하고, 청록 계열로 선택 탭과 주요 실행을 강조한다. 비활성 버튼은 상태를 보여 주되 기능 자체를 제거하지 않는다.

전체 UI 테마, 코드 편집기 테마, 다이어그램 미리보기 테마는 각각 별도다. UI Dark/Light 변경만으로 코드 내용이나 다이어그램 의미가 바뀌어서는 안 된다. 미리보기의 밝음/어두움은 SVG/PNG 출력 처리에도 전달된다.

현재 크기 규칙:

| 컨트롤 | 글자·크기 기준 |
| --- | --- |
| AI 공급자/모델/관련 버튼 | 12px, 기본 최소 높이 30px, 720px 이하 40px |
| 참고 텍스트·수정 동작 버튼, 코드/미리보기 탭 | 11px, 여백 4px 8px, 최소 높이 28px, 720px 이하 32px |
| 수정 코드·수정 프롬프트 라벨 | 12px |
| 수정 소스 코드 | Consolas 계열 13px/1.6, 기본 최소 높이 280px |

CSS에는 누적된 반응형/후속 규칙이 있으므로 앞쪽 선언 하나만 보고 최종 디자인을 판정하지 않는다. 구체성, 선언 순서, 현재 클래스와 `[open]`/`[hidden]`을 함께 확인한다.

## 4. Jena ME 상태와 모델 연결

Jena ME는 저장값이 없으면 접힌 상태다. 접기 버튼은 남기고 공급자·모델·입력 탭·입력 본문·AI 동작/피드백·기록 패널을 숨긴다. 펼치면 기존 컨트롤을 다시 사용할 수 있다. 모델 details는 초기화 시 `open = true`이며, Jena ME 전체 접기와 독립적인 내부 disclosure다.

최근 수정에서 열린 모델 details의 flex 선언을 `:not(.ai-collapsed)`로 한정했다. `[open]`이 전체 접힘을 덮어쓰지 않도록 한다. 접기 버튼은 normal flow의 grid 1행, 모델 설정은 2행을 사용하며, 공급자 행은 폭이 부족하면 줄바꿈한다. 버튼을 absolute로 덮어 놓거나 가로 클리핑으로 모델 동작을 숨기지 않는다.

공유 picker의 공급자 목록은 LM Studio, LiteRT-LM, AI Studio, Ollama, DeepSeek, OpenAI Compatible, Lemonade FLM NPU, Lemonade, OpenAI와 Jena 설정 사용이다. 선택값·설치 목록·자격 증명에 따라 실제 사용 가능 여부가 다르다. 목록에 있다는 사실은 현재 연결됨이나 비전 지원을 보장하지 않는다.

| 동작·상태 | 의미 |
| --- | --- |
| 모델 목록/저장된 ID | 선택 가능한 목록 또는 이전 선택. 연결 검증과 별도 |
| 미확인 | 저장값만 있거나 모델이 변경되어 확인 필요 |
| 확인 중 | 연결 조회 또는 모델 로드 진행 |
| 연결됨 | 해당 조회/로드/응답 경로에서 성공 확인. 이미지 인식 정확도 보장은 아님 |
| 연결 실패 | 통신·로드 등 오류. 세부 설명을 로컬 상태 메시지에 표시 |
| 모델 새로고침 | 강제 목록/연결 재확인 |
| 모델 로드 | 지원하는 로컬 공급자의 적재 요청 및 완료 확인 |
| 이미지 점검 | 지원되는 경로에서 실제 이미지 전송/응답 점검. 한글·표 재현 품질은 별도 |

모델 ID 직접 입력도 지원한다. LiteRT-LM 추가 인증 UI는 adapter가 unlock을 제공할 때만 노출한다. 호스트 ENV 인증 경로와 중복 입력을 강제하지 않는다. 로드 진행률은 0/5/15/50/90/100 등의 단계 표시이며 서버가 제공한 실제 적재 백분율이 아니다. 생성 진행률도 요청·수신·완료 단계 기준이다.

## 5. 네 가지 입력 탭

### 5.1 이미지

파일 선택, 드래그앤드롭, Ctrl+V와 클립보드 버튼을 지원한다. 업로드 미리보기, 제거, 크게 보기 컨트롤이 있다. 크게 보기/Crop 경로는 별도 창에서 이미지를 확대하고 원본 픽셀 좌표의 선택 영역으로 자른다. 적용 전에는 기존 참고 이미지를 유지한다. 팝업 차단·클립보드 권한 실패는 별도 처리한다.

이미지와 참고 텍스트를 함께 보내는 생성 경로가 있다. 현재 보이는 탭을 바꾸는 것만으로 다른 참고 입력을 자동 삭제하지 않는다.

### 5.2 참고 텍스트

직접 입력, 텍스트 붙여넣기, 파일 가져오기, 문서 선택 가져오기, 비우기를 제공한다. 파일 입력은 txt/md/markdown/csv/tsv/json/mmd 및 text/*를 허용한다. 최근 요청으로 `이미지 없이도 Jena ME 실행 가능 · 이미지와 함께 사용 가능` 안내 문구는 제거했다. 안내 삭제와 무관하게 텍스트 단독 생성 기능은 유지한다.

문서 선택 가져오기는 부모 창에 `target: reference-text`를 전달한다. 아래 코드 편집기의 문서 선택 가져오기와 목적지가 다르다.

### 5.3 가져온 코드 수정

상단 공통 `revision-toolbar`의 왼쪽에 현재 코드 가져오기, 오른쪽에 코드/미리보기 탭을 둔다. 아래 왼쪽은 수정 소스/미리보기, 오른쪽은 수정 대화·프롬프트·실행/중지/적용이다. 760px 이하에서는 기존 CSS에 따라 1열로 바뀐다. 모바일 버튼 크기 전환점 720px와 구분한다.

코드 보기와 미리보기는 같은 수정 소스를 사용한다. 수정 미리보기는 Dark, 확대/축소, Reset, PNG DN을 제공한다. 하단 전체 편집기의 미리보기와 별개다.

수정 요청은 `mode: edit`으로 코드와 수정 지시만 보낸다. 참고 이미지와 참고 텍스트는 제외한다. 코드와 지시가 모두 있어야 실행 가능하며, 요청 중에는 중복 요청과 입력 충돌을 제한한다. 중지는 실행 중에만, 적용은 유효한 준비 결과가 있을 때만 가능하다.

결과는 코드 추출 → 제한된 문법 복구 → `mermaid.parse` 검사를 거친다. 유효하면 수정 소스에 반영한다. 요청 시작 당시의 하단 편집기와 현재 내용이 같을 때만 하단에도 자동 적용하고 undo 상태와 기록을 남긴다. 사용자가 그동안 하단을 수정했다면 새 편집을 보존하고 수동 수정 결과 적용을 사용한다. 문법 검사 실패 결과를 정상 코드로 자동 적용하지 않는다.

### 5.4 저장 기록

생성/적용 기록은 부모 앱의 inDB 경로를 사용한다. 검색 대상은 코드·프롬프트·이미지 이름이며 최신순으로 표시한다. 코드 불러오기와 확인 후 삭제를 제공한다. 로컬 저장 실패 시 생성 성공과 기록 실패를 구분해 안내한다.

기록에는 코드, 프롬프트, 이미지 이름·data URL, createdAt 등이 포함된다. 수정 기록은 코드 수정 이름으로 구분하고 이미지 data URL을 비운다. 부모의 `InDbStorage`와 `mermaid_refs` store에 의존하며, AI 요청을 실행했다는 것과 영구 저장 성공은 별도다.

## 6. 코드 편집·렌더 기능

`raw-code-editor`는 일반 textarea 기반이다. 샘플 로드, 방향 TD/LR, Config 삽입, 12종 노드 모양과 노드 텍스트, 노드 전체/속성 모드, 연결 종류·라벨 모드로 코드를 조립한다. 연결은 실선/굵은선/점선/역방향/양방향/원·X 마감/라벨/다중 입출력/체이닝 등을 지원한다. 모든 샘플 유형에서 방향 변경이나 노드 생성이 같은 의미로 동작한다고 가정하지 않는다.

샘플에는 Flowchart, Sankey, State, Class, Sequence, ER, Journey, Mindmap, Pie, Timeline, Quadrant, XY Chart, Block, Kanban, Treemap, Requirement, Gantt, Architecture, Radar, Venn, Ishikawa, TreeView, GitGraph 등이 있다. 선택지 존재와 모든 버전의 렌더 호환성 검증은 구분한다.

주요 렌더 함수는 `debounceRender`, `preprocessMermaidSourceForRender`, `render`, `renderWithStartupRecovery`, `polishRenderedMermaidSvg`다. Markdown 코드 fence 제거, 라벨 안전 처리, 오류 SVG 탐지와 오류 메시지 영역이 있다. 오류 자동수정은 라벨/구문 안전 처리를 돕는 기능이며 의미 보존을 검토해야 한다.

편집기·미리보기는 각자 테마와 확대/축소/Reset을 갖는다. 미리보기는 휠 줌, 드래그 이동, 크게 보기 창을 지원한다. 데스크톱 분할 경계 드래그로 편집기·미리보기 폭을 조절한다. 크게 보기는 현재 렌더 결과를 사용하며 소스를 임의 변경하지 않는다.

| 단축키 | 동작 |
| --- | --- |
| Ctrl/Command+Z | 커스텀 undo 상태가 있으면 복원 |
| Ctrl+Alt+↓ 또는 Alt+Shift+↓ | 현재 줄 복제 |
| Ctrl/Command+/ | Mermaid 주석 전환 |
| Alt+↑ / Alt+↓ | 현재 줄 이동 |
| 탭 목록 방향키 | 해당 탭 선택·포커스 이동 경로 |
| 이미지 업로드 영역 Enter/Space | 이미지 파일 선택 |

## 7. 문서 삽입과 출력

| UI | 동작 |
| --- | --- |
| 코드로 문서삽입 | 부모에 Mermaid 코드 전달, 문서 코드 블록 삽입 경로 |
| SVG ← / PNG ← | 렌더 이미지를 부모의 이미지 넣기 UI로 전달 |
| SVG / PNG 다운로드 | 현재 렌더 결과를 파일로 저장 |

SVG 직렬화와 PNG 래스터화는 image-export.js 및 `serializeRenderedSvg`, `createRenderedPngBlob` 경로를 확인한다. 이미지 넣기 열기와 최종 문서 삽입, 다운로드 요청과 OS 파일 저장 성공은 각각 별도 단계다. iframe만 단독 실행하면 부모 문서·inDB·AI 브리지 기능이 제한된다. 이 문서는 DOCX/PDF·OS 인쇄 출력 준수를 보증하지 않는다. 해당 경로 변경 전 PRINT_PDF_RULES.md와 MATH_RENDER_RULES.md를 적용한다.

## 8. 부모 앱 연동·비동기 처리

내부에서 AI 공급자를 직접 새로 구현하지 않고 `postMessage`로 부모의 AIChat/AIChatBridge를 호출한다. 부모는 Mermaid iframe에서 온 요청을 식별하고, 자식의 수신기는 `event.source === window.parent`를 확인한다. 메시지는 와일드카드 targetOrigin을 사용하므로 출처 검증 구현을 포함한 보안 검토를 별도로 유지한다.

| 요청 | 응답/역할 |
| --- | --- |
| mdv-task-models-request | mdv-task-models-result: 모델·공급자 정보 |
| mdv-task-model-load-request | mdv-task-model-load-progress / result: 로드 단계·결과 |
| mdv-analyze-image-to-mermaid | mdv-image-to-mermaid-stream / progress / metrics / result |
| mdv-cancel-image-to-mermaid | 부모 요청 취소 |
| mdv-request-document-selection | mdv-load-document-selection / mdv-document-selection-unavailable |
| mdv-paste-mermaid-image / text | mdv-mermaid-clipboard-image / text |
| mdv-insert-mermaid | 부모 문서에 코드 삽입 |
| mdv-open-mermaid-svg-in-image-insert / png-in-image-insert | 부모 이미지 넣기 창 |
| mdv-mermaid-history-save / list / delete | mdv-mermaid-history-saved / records |

AI 요청은 requestId로 스트림과 최종 응답을 연결한다. 코드 수정은 요청 당시 소스·프롬프트·편집기 스냅샷을 보관한다. 응답 제한 시간은 자식에서 185000ms이며 취소 메시지와 실패 상태를 처리한다. 일반 생성에서 스트림 전 실패하면 이전 코드를 복원하는 분기가 있다. 이미 수신된 부분 결과를 항상 지운다고 가정하지 않는다.

생성 성능 표시는 경과 시간과 토큰 관련 지표를 사용하며 추정치 표시를 구분한다. 스트림 수신, 연결 성공, 문법 검증 통과, 실제 다이어그램 내용 정확성은 각각 별도로 평가한다.

## 10. 반응형·접근성 보존

모바일은 상단 메뉴 압축, 입력 탭, 코드/미리보기 전환을 사용한다. 여러 breakpoint가 공존하므로 390/560/720/760/767/900/1200px 전후를 확인한다. 가져온 코드 수정의 760px 1열, 컨트롤의 720px 크기 규칙을 혼동하지 않는다.

탭은 role=tablist/tab/tabpanel, aria-selected/controls/labelledby와 tabindex를 사용한다. disclosure는 네이티브 details/summary, 연결·오류·진행은 status/live 영역을 사용한다. 이미지 dialog는 닫은 뒤 업로드/크게 보기로 포커스를 복귀한다. 이름만 변경할 때도 기존 ID와 이벤트 바인딩을 유지한다.

최근 UI 작업에서는 AI Jena UI 계약과 접기 검사 33개, npm run build가 통과했다. 이는 당시 증거이며 이번 문서 작성에서 빌드를 다시 실행하지 않았다. 최근 안내 삭제·버튼·도구 행 변경의 실제 화면은 브라우저 소켓 폴더 권한 오류로 검증하지 못했다. 이전 변경 문서의 브라우저/실모델 성공 이력을 최신 UI의 live 검증으로 대체하지 않는다.

## 12. 상대 앱 이식과 Tauri

대상은 `C:/CusorApps/MDPRO/MDproViewer`다. 앞선 작업에서 대상의 내부 HTML·CSS·공유 picker 존재와 일부 차이를 읽기 확인했다. 이번 종합 문서는 대상 전체 기능의 일치 여부를 검증하지 않았다. **대상 확인 필요·미이식**으로 취급한다.

이식 시 대상 AGENTS.md와 이 문서, 관련 변경 문서, 출력/수식 계약을 읽고 DOM·부모 브리지·선택 저장·inDB·이미지 다운로드를 대응표로 먼저 비교한다. WebDAV 경로에서 mdpro/만 제거하거나 전체 파일을 덮어쓰지 않는다. 프런트엔드 적용, 웹 검증, Tauri 자산 포함, native 빌드, 설치 앱 검증을 구분한다. 이번은 문서 전용이므로 재귀 handoff나 새 Tauri 빌드 작업은 만들지 않는다.

```text
C:/CusorApps/MDPRO/MDproViewer에서 AGENTS.md와 WebDAV docs/mdpro-development/MERMAID_REF_UI_FUNCTIONS.md를 읽고 Mermaid Ref의 실제 UI·기능 대응표를 작성해줘. 대상의 독립 코드를 유지하고 미구현·차이·미검증 항목을 구분해줘. 이식 요청이 주어지면 해당 기능만 개별 패치하고 문서·색인·Tauri 대기를 갱신해줘. 문서 조사만으로 자동 이식·빌드·커밋·배포하지 마.
```
