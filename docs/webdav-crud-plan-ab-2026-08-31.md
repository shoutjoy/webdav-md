# NAS CRUD: PLAN A / PLAN B

## 동작

- 파일·폴더 이동/이름 변경/선택 이동은 공통 엔진 `moveRemoteItemVerified`를 사용한다.
- **PLAN A**: SDK `MOVE` 사용 → 대상 존재 + 원본 부재 확인. 로컬에서는 기존 Vite 프록시가 Destination을 NAS 주소로 변환하고, 공개 앱에서는 NAS 주소를 사용한다. 기본 `Overwrite: F`를 유지한다.
- **PLAN B**: MOVE의 기능 미지원/통신 오류(400/405/500/501/502/503/504/상태 없는 네트워크 오류) 시 원본·대상 상태를 조회한다. 원본이 남아 있고 대상이 없을 때만 GET → PUT → 대상 GET 바이트 비교 → DELETE → 원본 부재 확인으로 전환한다. DAV COPY는 사용하지 않는다.
- 401/403/404/409/412/423에서는 PLAN B로 권한·잠금·충돌을 우회하지 않는다. 응답이 소실되어도 이미 이동된 경우에는 성공으로 확인하고 다시 복사하지 않는다. 양쪽 모두 존재하거나 결과가 애매하면 중단한다. 기존 대상을 덮어쓰는 MOVE가 실패한 경우에도 자동 PLAN B 덮어쓰기는 하지 않는다.
- 폴더 PLAN B는 재귀적으로 구조를 생성하고 **모든 파일 저장·내용 검증이 끝나야** 원본 삭제 단계로 넘어간다. 삭제 중 오류가 발생하면 양쪽 경로가 남을 수 있다. 원본 폴더에 새 파일이 생겼으면 비어 있지 않으므로 폴더 삭제를 중단한다.
- 새 Markdown 파일 생성은 `overwrite: false`로 서버에서도 이름 충돌을 차단한다. 편집 저장/다른 이름으로 저장/새 파일 생성은 다시 읽은 내용까지 비교한다. 저장 조건 실패(false 반환)를 성공으로 표시하지 않는다.
- 삭제는 서버의 응답 코드뿐 아니라 원본 부재도 확인한다. 폴더 삭제 시 열린 하위 문서와 마지막 텍스트 문서 참조를 정리한다. 폴더 이름 변경·이동 시 열린 하위 문서의 저장 경로를 갱신한다.
- 진행 표시에서 PLAN A / PLAN B를 구분한다. PLAN A는 NAS 내부 작업이라 서버가 세부 진행률을 제공하지 않는 동안 0%이며 확인 완료 후 100%이다. PLAN B는 처리 파일/폴더 수 기준이다.

## 실제 NAS CORS 점검 (2026-08-31)

`node scripts/check-webdav-cors.mjs`는 인증 없이 OPTIONS만 실행한다. 외부 파일을 생성/수정/삭제하지 않는다.

`https://shoutjoy.github.io`와 `http://localhost:5173` 각각에 대해:

| 요청 | 사전 허용 점검 |
| --- | --- |
| PROPFIND, GET, MKCOL, 일반 PUT, MOVE, DELETE | 통과 |
| PUT + If-None-Match | 실패: 허용 헤더 누락 |
| PUT + If-Match | 실패: 허용 헤더 누락 |

두 출처 총 16건 중 12건 통과. 응답의 `Access-Control-Allow-Origin: *` 및 메서드 목록은 확인했으나 허용 헤더는 `Authorization, Content-Type, Depth, Destination, If, Lock-Token, Overwrite`이며 **If-None-Match / If-Match가 없다**. `If`는 별개의 헤더로 이를 대신하지 않는다.

NAS/nginx의 기존 `Access-Control-Allow-Headers` 목록에 `If-None-Match, If-Match`를 추가해야 한다. 설정 권한이 없는 앱에서 이 보호 조건을 제거하지 않는다. 프리플라이트 캐시가 86400초이므로 설정 적용 뒤 브라우저의 이전 허용 결과 캐시에도 유의한다. 실제 요청 응답/오류 응답에도 CORS 허용이 필요하다.

현재 코드의 새 파일 생성과 PLAN B는 If-None-Match를 사용한다. If-Match는 향후 원본 동시 수정에 대한 조건부 요청을 위한 권장 헤더이며 현 엔진이 모든 원격 변경을 잠그는 것은 아니다.

## 검증 범위 / 남은 확인

- 자동 테스트: 기본 이동, 응답 소실, PLAN B 전환, 권한·잠금·충돌 중단, 파일/폴더 생성·수정·조회·삭제, 폴더 중간 저장 실패 시 원본 보존, 삭제 결과 검증.
- 실제 WebDAV SDK + 로컬 HTTP 서버에서 PLAN A와 PLAN B 모두 한글 파일 생성 → 수정 → 이름 변경/이동 → 폴더 이동 → 내용 확인 → 파일/폴더 삭제 통과.
- 실제 브라우저에서는 Edge 공개 WebDAV 앱의 로그인된 트리를 확인했다. Codex 로컬 브라우저는 로그인 화면이었다. 브라우저 인증 정보는 조회하지 않았다.
- **실제 NAS에 테스트 자료를 쓰거나 지우는 검증은 사용자 확인을 기다리고 있다. OPTIONS 통과나 로컬 HTTP 테스트를 NAS CRUD 성공으로 해석하지 않는다.**
- 로컬 소스/빌드 변경이며 공개 GitHub Pages 배포는 수행하지 않았다.
- PLAN B는 파일 내용을 메모리로 읽으므로 대용량 파일에서 메모리/전송시간 비용이 크다. 서버가 GET/PUT/DELETE까지 막거나 완전히 끊기면 PLAN B도 불가능하다. 메타데이터/잠금/권한 복제, 동시 수정에 대한 원자적 보호, 원격 작업 전체 Undo/Redo는 이번 보장의 범위에 포함되지 않는다.

## NAS 실제 검증 절차

사용자가 허용한 `codex-crud-check-20260831` 전용 폴더 안에서만 작은 테스트 문서를 생성·읽기·수정·파일명 변경·하위 폴더 이동·폴더 이동·파일/폴더 삭제한다. 기존 문서/폴더는 변경하지 않는다. 결과 확인을 위해 새로고침 후 경로와 내용도 검사한다. 수정한 로컬 앱에 사용자가 로그인하면 새 엔진을 검증할 수 있다. 기존 공개 앱의 검증 결과는 공개 버전에만 해당한다.
